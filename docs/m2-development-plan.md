版本：1.0.0。确认日期：2026-10-22；更新日期：2026-10-23。状态：M2-01 契约、M2-02 模型准备、M2-03 数据转换/监督标签已完成；M2-04 真实训练/基础保存已完成；M2-05 独立产物审计/保存故障验收已完成，M2-06 新进程重载待完成。

## 一、目标与进入条件

在本地 WSL2 + RTX 5070 12GB 上，使用真实的 `Qwen/Qwen2.5-0.5B-Instruct` 完成普通 LoRA 微调，产生可追溯的 Adapter，并在结束训练进程后启动新进程重载、生成回答。

M2 演示流程：准备模型缓存 → 检查训练样本 → 命令行训练 → 查看真实指标与产物 → 退出训练进程 → 新进程加载基础模型和 Adapter → 生成文本。

## 二、范围与交付层次

M2 必须交付模型缓存、数据转换、独立训练入口、真实指标、Adapter/配置/清单、独立重载和验证记录。首个模型固定为 0.5B，保持单 GPU，先使用现有依赖与普通 LoRA。

M3 负责任务 HTTP API、Celery 业务调度、数据库状态与重复投递处理；M4 负责指标/日志 HTTP、Loss 页面联调和 Adapter 下载；M5 负责在线推理、GPU 互斥服务与部署。M2 的本地重载生成是训练产物验收，不表示推理服务已实现。

不在本阶段增加量化、多 GPU、FlashAttention 等额外兼容性组件、Kubernetes、自动调参、取消或断点续训。`checkpoints/` 如有写入只作为诊断与检查点产物，不承诺恢复功能。

区分两层交付：

- **工程闭环是 M2 完成条件**：极小数据上的真实 LoRA 更新、有限且真实的指标、有效产物和新进程重载。格式草稿允许用于该层，但必须记录未审核状态，不能据此声称效果提升。
- **正式效果实验是并行推进的实验工作**：使用审核后的领域数据包与既有评测规范。M2 开始整理数据并尝试小规模完整训练，100–300 条目标和完整双人评分按质量与工时持续推进，在后续正式实验阶段验收；不能把这些尚未完成的工作计作 M2 成果。

## 四、各任务实施与验收

### M2-01：先确定训练契约

本项已交付 [内部训练契约 1.0.0](contracts/training.md)。代码在 trainer/contracts.py，旧 trainer.train 导入位置保留；真实训练入口已在 M2-04 实现。

| 类型 | 原占位字段 | 已定稿的 v1 扩展 |
| --- | --- | --- |
| TrainRequest | task_id、dataset_path、output_dir、base_model、config | 必填 model_revision/cache_dir/log_path，可选验证集/数据清单、RuntimeOptions |
| TrainingConfig | LoRA、学习率、epoch、batch、梯度累积、长度、日志频率、seed | 保持不变；precision/max_steps/local_files_only 属于独立内部 RuntimeOptions |
| TrainingProgress | step、total_steps、loss | 必填 learning_rate/epoch/recorded_at，kind 区分 train/eval |
| TrainResult | adapter_dir、metrics_path | 必填 tokenizer_dir/config_path/manifest_path；文件校验已由 M2-05 实现 |

契约文档、生成的 JSON Schema 和格式样例已交付，写明版本、默认值、单位、必填/可选、失败语义及当前实现状态。使用 scripts/export_training_contract.py 导出，--check 检查漂移；Schema 保持 CPU 可导入，模型依赖在后续执行训练时加载。示例数值全部为格式占位，不是实验结果。

保留已有字段含义；鉴于旧接口仅为未发布占位，v1 显式要求固定 revision 和完整定位信息，迁移至 Pydantic 关键字构造，具体必填变化见契约。后续兼容扩展优先采用可选字段。`max_steps` 等冒烟选项只供内部运行，不扩大前端表单或任务 API；公共参数与数据集 HTTP 契约不变，不为内部训练字段手改 OpenAPI；后续公开 HTTP 字段时从真实应用重新导出并检查。

**验收**：A、B 使用同一份输入、事件和产物样例即可说明调用流程；字段与现有类型无未解释冲突；说明哪些类型修改已落地、哪些功能仍待实现。

### M2-02：固定模型与可复用缓存

本项已交付 scripts/prepare_model.py、trainer/model_cache.py、独立 GPU probe 与行为检查，使用与配置见 [模型缓存说明](model-cache.md)。固定 revision 的 9 文件缓存和离线 GPU 前向均已实际通过；下面约定继续供后续任务复用，不表示已训练 Adapter。

检查已有缓存，按需下载模型和 tokenizer，记录最终解析到的不可变模型 revision。训练与重载使用相同 revision，不能只记录会变化的分支名。

缓存沿用 `DATA_DIR/models/huggingface/` 规划，处理配置目录和 HF 缓存目录的关系；现有 `.env.example` 中 HF_HOME 仅是环境配置，不代表训练入口已实现路径初始化。不能硬编码成员机器的绝对路径或代理，不能仅假定 Python 自动加载 `.env`。Trainer 的配置解析保持独立于后端 Settings。

提供明确的缓存/检查入口，验证 tokenizer、模型配置与真实权重可读取，并执行最小 GPU 前向。首次准备允许联网，后续本地缓存检查应能明确禁止在线回退，缺文件或 revision 不匹配给出可定位错误。模型目录 API 仍只表示白名单，不因此声称缓存可用。

**验收**：记录模型 ID、解析后 revision、加载精度与环境；已有完整缓存时可离线加载；下载失败不被视为缓存完成，不提交权重或访问令牌。

### M2-03：检查样本、模板与监督目标

本项已交付 trainer/preprocessing.py、trainer/dataset_manifest.py、scripts/check_training_data.py 和 CPU 行为检查，见 [数据处理说明](training-data.md)。真实 tokenizer 的标签、截断与 CPU 张量批次已验证；本次按用户要求由当前侧实现，后续 B 接续 Trainer，不表示已执行训练或完成正式语料审核。

通过 `iter_records` 读取标准 instruction/input/output；instruction 与非空 input 按固定、可记录的方式组成用户消息，output 组成助手回答，使用固定基础模型的 chat template。训练和重载沿用相同对话约定，不手工拼接另一套特殊 token。

本阶段以助手回答为监督目标，检查用户/系统内容和 padding 的标签屏蔽、回答结束标记与特殊 token 处理。先检查当前锁定版本和模板是否支持所需标签掩码；不能仅打开某个配置项便假定掩码正确。

提供小样本诊断，能核对实际 token、标签与有效监督 token 数；默认日志不输出完整训练正文。明确截断方向与策略，样本无有效监督目标时给出错误，不静默训练空目标。上传格式合法不保证适合当前 token 长度，两个层面的错误分别记录。

正式数据复用 `scripts/prepare_dataset.py`，保留 build_id、哈希、问答族、seed 和审核状态。validation 只作开发选择；test 在参数确定后评估；冻结 12 题及其族独立保留，不参与训练、验证或调参。

**验收**：有/无 input、padding、边界长度、截断后无回答等行为有检查；真实 Qwen 模板下人工检查至少一个样本；数据拆分规则和上传格式不被改写。

### M2-04：实现真实 LoRA 与独立 CLI

本项已交付 [训练入口](training.md) 及 [实测日志](worklogs/2026-10-23-m2-04.md)。为遵守 TrainResult 成功条件同时接入基础保存/清单；M2-05 现已补齐独立产物校验和保存故障验收，M2-06 新进程重载仍待完成。以下要求为后续维护基线。

实现 `train(request, on_progress) -> TrainResult`，CLI 与后续 Worker 复用该函数。优先复用现有 Hugging Face/PEFT/TRL 能力，具体 API 以 `uv.lock` 对应版本为准，避免为实现训练重写一套训练框架。

初始参数保持当前契约：r=8、alpha=16、dropout=0.05、q_proj/v_proj、batch=1、梯度累积=8、长度=512、epoch=1、learning_rate=2e-4、seed=42。真实基础模型的 BF16 前向已验证，LoRA 反向/优化器已在 M2-04 实测；实际精度写入清单，不静默改变参数。打印/记录总参数量、可训练参数量和目标模块，确认基础模型参数冻结。

先执行极少量优化器更新，再尝试小规模完整训练。`step` 统一指优化器更新步数，不用微批次计数冒充进度；`total_steps` 与实际数据量、梯度累积和停止条件一致。Loss 按训练框架真实日志语义保存，不声称每个点是单条样本的 Loss。

Trainer 是 `metrics.jsonl` 的唯一写入方，进度回调提供同源事件；后续 Worker 只消费事件、更新数据库状态，不重复追加指标。加载阶段只记阶段日志，无 Loss 时不补 0；train/eval 指标明确区分。训练未提供验证集时不产生虚构 eval_loss。

CLI 成功返回 0，配置、模型、数据、OOM、指标/产物写入或核心回调失败返回非零并保留原因。异常不被吞掉，不自动无限重试或偷偷降低配置；按生命周期释放模型和 GPU 引用。

**验收**：真实模型在本机完成优化器更新，Loss 有限；有证据确认 LoRA 权重发生更新，基础参数保持冻结；进度、日志与实际训练一致。CPU API 启动不需要安装训练依赖。

### M2-05：输出可追溯、可校验的产物

本项已交付 [共享审计器与 CPU 命令](training-artifacts.md)、排他原子提交与保存故障验收，见 [日志](worklogs/2026-10-23-m2-05.md)。M2-04 基础保存已接入同一校验器；已审计此前真实产物并完成一次新保存联调，尚未执行 M2-06 模型重载。

目录与相对路径语义已由 [M2-01 契约](contracts/training.md) 定稿；本任务实现真实保存与校验：

```text
DATA_DIR/
├── models/huggingface/
└── outputs/{task_id}/
    ├── adapter/                 # Adapter 权重与配置，不复制基础模型权重
    ├── tokenizer/               # tokenizer、特殊 token 与模板信息
    ├── checkpoints/             # 可选；无检查点时可不创建
    ├── metrics.jsonl
    ├── training_config.json
    └── manifest.json
LOG_DIR/
└── tasks/{task_id}.log
```

每次 CLI 运行生成或使用明确的 UUID，服务任务 ID 后续由 M3 提供。拒绝覆盖已有任务目录；内部路径由受控入口解析，不新增让 HTTP 客户端提交服务器路径的能力。

清单至少记录契约版本、任务 ID、模型与 tokenizer revision、模板信息、数据哈希/样本数/审核状态、完整参数、seed、实际精度、代码 commit/工作区是否有改动、uv.lock 哈希和运行库版本。记录实际完成步数、耗时、显存峰值及产物相对路径与哈希，单位明确。吞吐量若记录，说明是样本/秒还是 token/秒及统计口径。

无法从原始上传文件确认来源/审核时明确记为未知，不根据格式合法推断 reviewed。清单与可分享摘要不写本机绝对路径、训练正文或凭据。

先保存与校验必需文件，再原子写出成功 manifest，最后返回 TrainResult；manifest 是本地成功结果标记，不替代 M3 数据库状态。失败可保留本次目录中的诊断或部分产物，但不能保留有效成功标记，不能删除其他任务或源数据。M2-06 的新进程验收单独记录，不在训练保存时提前声称已重载成功。

**验收**：必需文件存在且配置可读取，哈希与引用一致，缺文件/错误 revision/已有目录被拒绝；正式数据、缓存、日志和运行产物均被 Git 忽略。可供未来下载打包，但 M2 不实现下载 API。

### M2-06：新进程重载、失败验收与记录

训练结束后启动独立进程，读取结果清单，加载同一基础模型 revision、保存的 tokenizer 与 Adapter，再执行固定开发提示词生成。校验输入产物、模型匹配与实际 Adapter 加载，不能只验证训练进程内仍可生成。

工程重载使用独立开发提示词，不反复查看冻结题调参；正式对照实验再按 [既有评测协议](data/README.md) 执行。少量训练后生成文本不变可以是正常现象，验收同时检查权重更新、产物和加载证据，不要求回答必须改变或评分必须提升。

验证覆盖：正常保存/重载、非法配置/数据、缺模型缓存、无有效监督 token、拒绝覆盖、产物不完整或保存失败。OOM 如实际发生保留现场；CPU 可用受控异常检查错误传播与清理，明确它不是实测 OOM，不故意耗尽整机资源。无需为文档或小修反复重训。

交付可执行命令、GPU 结果与失败证据到新工作日志；真实实验汇总写入 `experiment.md`，原始生成回答放忽略的 `data/experiments/`。CPU CI 保持无需 GPU 或下载真实权重，真实 GPU 验收在本机单独执行。

**验收**：训练和重载为不同进程，有真实生成输出与可复现条件；失败不返回成功；说明未测项及正式语料审核进度。完成阶段前同步 README、项目记忆、总规划、协作入口与日志索引。

## 五、文件归属与协作交接

| 范围 | 默认主改方 | 配合方式 |
| --- | --- | --- |
| `trainer/train.py` 与训练主体 | B | A 不并行改同一入口，通过契约和独立辅助模块接入 |
| 数据转换与重载生成入口 | B | A 复核数据边界、失败行为与证据 |

| `frontend/` | B | M2 不安排界面业务改动；如确需调整，单独说明并执行受影响回归 |
| 正式语料 | B 编写、A 交叉审核 | 数据留在忽略目录，不能由 AI 自动标记 reviewed |

这用于避免重叠编辑，不新增文件访问审批；用户明确调整分工时以用户要求为准。开始各任务前说明主改文件，交接记录输入、输出、已测/未测和下一位成员的调用方式。

每次开发开始前、每个独立部分完成后、最终提交/推送前都 fetch、比较远端、阅读队友新增提交和日志。工作区干净且落后时优先 ff-only；分叉时保存本次提交后正常 merge 并重跑受影响检查，保留他人未提交改动。无法访问远端则记录尚未确认，不强推或覆盖文件。

每项任务新增 `docs/worklogs/YYYY-MM-DD-m2-XX.md`，包含起点 commit、主改文件、接口影响、命令/结果、Git 同步结果、未完成项和交接。未执行的命令写为计划，不能写成通过。

## 六、执行入口与回归边界

以下环境命令已存在，按当前机器状态执行；本文件没有替用户运行 GPU 检查或下载模型：

```bash
uv sync --locked --extra training
uv run --locked --extra training python scripts/check_gpu.py
```

模型准备/检查入口已由 M2-02 交付，见 [命令说明](model-cache.md)。训练 CLI 已由 M2-04 实现，使用 `python -m trainer.train`，见 [命令与语义](training.md)；Adapter 重载入口仍待 M2-06。训练机器后续同步保留 training extra；仅 CPU 回归使用独立环境，避免普通 uv sync 卸载 GPU 依赖。

CPU 回归聚焦共享校验、配置、事件/清单、路径隔离与错误处理；模板检查可使用缓存 tokenizer，本地 GPU 测试加载真实预训练模型。小型随机模型可检查算法，但不能替代本阶段真实模型验收。未改前端无需重复完整浏览器回归；修改共享配置或接口时运行对应检查。
