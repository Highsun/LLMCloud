课程展示重点包括 HTTP 服务、异步任务队列、GPU 串行调度、数据与模型产物管理、过程观测和部署复现。

## 二、范围与技术决策

| 项目 | 八周内的约定 |
| --- | --- |
| 基础模型 | 首先只支持 Qwen2.5-0.5B-Instruct |
| 微调方式 | 普通 LoRA；初始 batch=1、max_seq_length=512，精度和参数按实测确定 |
| 数据格式 | 先支持 UTF-8 JSONL 的 instruction/input/output，上传上限 50 MiB |
| 服务 | FastAPI 处理请求和元数据，Celery Worker 执行 GPU 工作 |
| 任务状态 | PENDING、QUEUED、RUNNING、COMPLETED、FAILED，数据库为业务状态来源 |
| GPU | 单 GPU、单训练 Worker；推理与训练共享资源互斥 |
| 前端 | Vue3，按功能逐周交付，先轮询进度与指标 |
| 元数据与文件 | 本地和单机云部署先使用 SQLite + 持久化文件目录 |
| 用户模式 | 单用户课程演示；云端入口采用访问限制，公开多人使用前另做认证授权 |
| 依赖 | uv + uv.lock；训练机器同步时启用 training extra |
| 部署 | 先本地端到端，再 Docker Compose，再迁移到一台可用的云服务器 |

1.5B 模型、QLoRA、多种数据格式、取消/断点续训、多租户、计费、多 GPU、Kubernetes、WebSocket 和完整监控平台均不进入基础排期。完成验收后再选择扩展项。

云端 CPU + 本地 GPU 属于备选部署方案。它需要集中数据库、文件传输或对象存储以及网络连通方案，不能直接共享 SQLite 或云端本地文件路径。第 3 周结束前确认云资源条件；若必须采用混合部署，应重新估时，优先调整展示范围或增加时间。

1. 缓存 Qwen2.5-0.5B-Instruct，并记录模型 revision；不依赖演示时临时下载权重。
2. 将 instruction/input/output 转为统一对话样本，使用基础模型的 chat template，检查截断与监督目标是否正确。
3. 从极少量步数开始，记录真实 Loss、步数、耗时、显存与可训练参数；再进行小规模完整训练。
4. 实现 `TrainRequest → train → TrainResult`，通过回调传递指标，保持 Trainer 独立于 HTTP 和 Celery。
5. 保存 Adapter、必要 tokenizer/template、参数快照和结果清单；在独立进程重载，避免只验证内存中已训练模型。

不以“训练后必须明显变聪明”为验收条件。服务链路和产物可用必须成立，模型效果通过固定测试问题与实验记录客观呈现。

### M3：把训练接入可靠的异步服务

- API 先持久化元数据，再发送仅包含任务 ID 的消息。正常 Broker 条件下，任务创建请求以本机约 2 秒内响应为性能目标，实测记录，不等待权重加载和训练。
- Worker 按条件领取任务，防止 API 的 QUEUED 更新覆盖 RUNNING；重复消息不重复启动训练。
- 只启动一个 GPU Worker，并发 1、预取 1；保存开始/结束时间、异常和产物位置。
- 完成状态必须晚于产物保存与校验；Broker 不可用时返回可读错误并保留可追踪的失败记录。
- 推理资源策略在此阶段确认，W5 复用 GPU Worker 执行推理，API 只负责调度，不额外加载一份 GPU 模型。

### M4：只展示真实训练证据

- 曲线读取逐行保存的真实指标；日志接口限制读取大小，前端先按约 2 秒轮询。
- 训练/模型加载阶段允许暂无 Loss，展示阶段状态；进度不能用定时器虚构增长。
- 只允许已完成且产物有效的任务下载 Adapter；失败或未完成任务给出明确状态。

### M5：推理、稳定与部署

- 推理设置提示词和输出长度限制、超时与 GPU 资源互斥；训练占用资源时返回需求契约中的 409。
- W6 覆盖正常训练、非法数据、Broker 不可用、训练异常、重复消息和 Worker 退出。对已确认失联的任务提供状态修正方式，保留原因，不自动重复训练或承诺断点恢复。
- Docker 中分别构建 CPU API/前端和 GPU Worker，持久化数据库、数据、模型缓存和产物。GPU 容器阶段再配置 NVIDIA Container Toolkit。
- 云端优先采用一台可用 GPU 服务器，减少跨主机存储和数据库改造。部署后至少完成一次真实训练与推理；镜像构建成功不等于云端业务验证成功。
- 课程演示入口先使用受限网络或受控访问，Redis/数据库不直接暴露公网。

## 八、实验与课程成果

选定一个小领域，例如云计算基础问答。初始正式实验可从 100–300 条来源清晰的样本开始，并单独划分验证与测试数据；样本量按数据质量和工时调整。保存固定测试问题，不混入训练集。

| 证据类型 | 需要记录的内容 |
| --- | --- |
| 可复现性 | Git commit、uv.lock、模型 revision、数据来源/摘要、数据划分、随机种子与参数 |
| 训练 | 总步数、真实 train/eval Loss、可训练参数、显存峰值、耗时、Adapter 大小 |
| 调度 | 两个任务的提交/排队/开始/结束时间，证明同一 GPU 没有重叠训练 |
| 稳定性 | 至少一项失败任务的错误信息、状态和后续处理 |
| 效果 | 相同提示词与推理解码设置下的基础模型/LoRA 输出，保留提升、无变化和退化案例 |
| 部署 | 服务拓扑、镜像与持久化配置、云端运行记录、启动和恢复步骤 |

最终交付：源代码与锁文件、可用 Web 平台、训练 Adapter 和清单、实验记录、部署说明、课程报告、PPT、5–8 分钟演示视频及演示脚本。正式答辩时长以老师要求为准。

## 九、风险与调整规则

| 风险或触发条件 | 处理方式 |
| --- | --- |
| W2 尚不能重载真实训练 Adapter | 优先修复训练链路，减少页面美化和实验组数；不加入更大模型或量化依赖 |
| 显存不足 | 保持 0.5B，先降低序列长度/批量，再按实测启用节省显存策略 |
| 数据效果不明显 | 检查数据、模板与监督目标；如实记录，避免仅追求训练 Loss 或临时扩大规模 |
| W3 尚不能串行执行两个任务 | 优先修复调度、状态和产物隔离，推迟交互增强 |
| 第 3 周仍未确认云 GPU 条件 | 明确预算、服务器和访问方式；如采用混合部署，单列 PostgreSQL/文件传输工作并重排工时 |
| Docker/模型网络不稳定 | 提前准备依赖、基础模型缓存和已验证镜像，演示前不执行在线升级 |
| W5 尚未形成完整闭环 | W6 优先补核心链路；停止扩展，不挤占最终报告和演练时间 |
| 截止前临时故障 | 保留已验证版本、缓存模型、Adapter、日志和演示视频；离线素材作为补充证据，不能冒充当前在线运行 |

赶工时依次减少：页面装饰、额外模型/格式、额外实验组、实时通信和高级恢复。必须保留真实训练、异步执行、任务状态、真实指标、Adapter 交付、测试推理和诚实的部署验证。
