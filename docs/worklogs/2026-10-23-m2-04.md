## 实现与接口

- trainer/train.py：沿用 train(request, on_progress) -> TrainResult，CPU 可导入；重新验证可变嵌套配置、解析真实路径、独占输出/日志、复用缓存与数据模块。异常保留本次 failure.json、日志及已 flush 指标，不返回成功。
- trainer/cli.py：python -m trainer.train；固定 revision、数据/验证集/清单、可选参数 JSON、内部 max_steps/precision、UUID 与根目录；显式读取 .env，设置离线/GPU 环境。stdout 只输出成功结果 JSON，进度到 stderr，失败非零。
- trainer/hf_training.py：执行时导入 Transformers Trainer、PEFT、torch/Datasets；单可见 GPU，BF16 或显式 FP32，不量化、不重新套模板或覆盖 labels。AdamW/线性调度/无 warmup/裁剪 1 等执行策略明确，参数默认值未改。
- trainer/events.py：校验真实有限指标、步数/顺序与总步数；write/flush 后调用同源回调。加载阶段无 Loss，框架 aggregate 日志不伪装成新步数。最后训练窗口补记；按需补末步验证。
- trainer/run_storage.py：配置快照、代码/锁文件/环境版本、已保存配置/模板/文件基础检查、大小与哈希清单，最后原子写成功 manifest。保存张量在执行层与训练后 Adapter 逐项核对。
- tests/test_training_execution.py：16 项 CPU 行为检查；原契约导入测试从“必须占位”更新为“非法请求在可选依赖导入前失败”。覆盖同源/flush、顺序/有限值、回调/写入失败、拒绝覆盖/链接别名、配置快照、CLI 退出/输出、受控执行异常及 CPU 导入。
- docs/training.md：运行、模块、指标、失败与 M2-05/06 交接；同步 README、AGENTS、规划/记忆、架构/需求、环境、契约现状、缓存/数据说明、实验与日志索引。历史工作日志保持原样。

## 故障与资源清理

真实回调在收到已 flush 的事件后抛出受控 RuntimeError，结果为 PROGRESS_CALLBACK_FAILED；已写事件保留，无 Adapter/成功 manifest，failure.json 和任务日志保留安全诊断。最终同进程连续两次任务：6de4a308-c9ad-4b7a-bb5f-43a513dd6aba、8e885c66-2228-408b-b8ef-7b644a54d5db，均通过。

最初错误地以 allocated_bytes 必须归零作为清理断言，验收脚本失败；进一步诊断没有存活 Python CUDA tensor，两次失败后的分配都为 18,087,936 字节，无累积。仅在诊断脚本清除 cuBLAS 工作区后归零，确认是库工作区缓存。最终成功路径也得到同样缓存值并在诊断清除后归零。正式代码释放模型/优化器及异常栈局部 GPU 引用，不调用 torch 私有工作区清除接口，不承诺 empty_cache 消除全部库缓存。

受控 CPU OOM/训练/保存异常检查验证错误保留、非零/不成功与无自动重试；未实测 OOM，不故意耗尽显存。没有新增取消、恢复、GPU 跨进程锁或任务调度，部署仍需保证同一卡不重叠执行。
