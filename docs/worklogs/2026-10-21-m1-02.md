## 三、服务行为与接口

下面示例假设已按需完成旧库迁移，并启动过后端以初始化数据库表。

```python
from backend.app.services.datasets import DatasetService
from backend.app.models.dataset_schemas import DatasetListQuery

service = DatasetService()
with open("docs/examples/train.jsonl", "rb") as source:
    dataset = service.create(source, filename="train.jsonl", name="课程样例")

detail = service.get(dataset.id)
page = service.list(DatasetListQuery(page=1, page_size=20))
```

以上示例会真实创建数据集，不能当作无副作用的环境检查反复执行。测试使用临时目录和数据库，本机实际数据库没有写入演示数据。

- `create(source, *, filename, name=None) -> DatasetDetail`：source 为阻塞式二进制流，从当前游标读至 EOF，调用者应放在文件开头并负责关闭；服务不会关闭调用者的流。
- `get(dataset_id) -> DatasetDetail`：UUID 语法错误为 VALIDATION_ERROR，不存在为 DATASET_NOT_FOUND；详情不读取原始文件。
- `list(query=None) -> DatasetPage`：默认页大小 20、固定时间/ID 倒序，超出末页不执行大 OFFSET 查询，直接返回空 items。
- `audit_storage(verify_hash=False) -> dict`：只读输出待核对候选项。先停止写入再进行人工修复，运行中的上传也可能暂时被列为候选。
- 可通过构造函数注入 Settings 和 session_factory，测试及将来的不同部署环境不依赖本机绝对路径。

### 上传与校验

每次最多从 source 读取 64 KiB，在临时文件写入前把该块送给扫描器。扫描器累计文件大小与原始 SHA-256，仅保留一条未完成物理行；超限立即拒绝，不先读取整份文件到内存。

已实现 UTF-8、起始 BOM、LF/CRLF、末行无换行、空白行跳过、物理行号、JSON 语法/重复键/NaN/Infinity、字段类型与未知字段校验。JSON 解码前检查结构嵌套，超过 128 层按 invalid_json 拒绝；合法指令记录只有字符串字段，不受此防护影响。训练文本不 strip、不截断、不改写，input 缺省只在读取结果中补空字符串。

保存顺序：校验名称与原始文件名 → 独占创建 `.tmp/{UUID}.part` → 分块扫描/写入 → flush/fsync 文件 → 创建独占 UUID 目录并移动 → flush 数据库并验证响应 DTO → commit。原始文件内容保持不变，数据库只保存相对 DATA_DIR 的键。

### 清理与提交结果

- 已确认失败：rollback，删除本次创建的临时/最终文件，再移除空目录；不递归删除、不清理其他上传拥有的文件。
- COMMIT 抛错：rollback 后使用新 Session 核验同 UUID、存储键与哈希。确认已提交则正常返回资源，确认未提交则清理。
- 核验也失败：保留文件，返回 DATABASE_UNAVAILABLE 并记录 dataset_commit_uncertain，后续通过只读审计和数据库状态排查。不能把“没有收到提交成功”直接当成“没有提交”。
- 清理失败：记录诊断，不覆盖原始业务错误，残留文件进入审计候选。
- 进程强杀或断电不保证 SQL 与文件原子提交；当前提供排查依据，不承诺自动修复或分布式事务。

服务错误不包含原始训练记录、Pydantic input、绝对路径或数据库异常文本。日志记录数据集 ID 和异常类型；request_id 的生成/关联与统一 ErrorResponse 由 M1-03 完成。

## 四、迁移操作

新库由启动流程直接创建新表。旧库启动会明确提示迁移，不会自动删库或把缺失信息填成虚假值。对其他数据库类型的迁移暂不支持。

停止 API/Worker 后执行：

```bash
uv run --locked python scripts/migrate_datasets.py --check
uv run --locked python scripts/migrate_datasets.py --apply
uv run --locked python scripts/check_dataset_storage.py --verify-hash
```

有历史记录时，需提供来自可信历史资料的原始文件名映射，例如在被 Git 忽略的 `data/migration-filenames.json` 中保存：

```json
{
  "已有数据集的实际UUID": "original-training.jsonl"
}
```

```bash
uv run --locked python scripts/migrate_datasets.py --check --filenames data/migration-filenames.json
uv run --locked python scripts/migrate_datasets.py --apply --filenames data/migration-filenames.json
```

迁移不会用显示名称或最终路径 train.jsonl 猜测原始文件名。缺失文件、旧统计与文件不一致、非法内容/路径、未知映射或不支持的表结构会阻止升级，输出待修复清单；不会静默改写原始文件或丢弃未知列/约束。

应用迁移前通过 SQLite backup 接口保存数据库到 `DATA_DIR/backups/`，包含已提交的 WAL 内容；随后在 BEGIN IMMEDIATE 中重新检查，创建替代表、复制数据、替换表、恢复索引/触发器、检查外键后提交。任何中间失败回滚。数据集 ID、用户引用、显示名、时间及历史训练任务均保留；原先规范路径的绝对形式转换为相对键。

本机已执行：ready（0 条）→ 自动备份 → applied → current，数据集与任务仍为 0 条，存储审计各项为空。备份保存在本机被 Git 忽略的 data/backups 下。恢复时应停止全部数据库连接，使用 SQLite backup/restore 方式处理，不直接替换仍在使用的数据库文件。

## 六、M1-03 接入说明与剩余工作

下一阶段解析 multipart、限制整个请求体与 part 数、拒绝重复/未知字段，再调用本服务。服务只控制实际文件与行的大小，不代表 HTTP 解析前的 50 MiB + 64 KiB 请求体限制已经落实。

异步路由应将阻塞的 service.create/get/list 放入线程池，上传文件游标先归零，文件在服务完成后由 HTTP 层关闭。不要复用调用者已有事务，因为 DatasetService 的提交与确认逻辑需要自己拥有独立 Session。

将 DatasetServiceError 映射为约定的 ErrorResponse，生成/关联 request_id，添加 X-Request-ID、Location 及 CORS 暴露；实现三条数据集路由并用真实 HTTP 与 OpenAPI 测试验收。Vue 页面和浏览器联调仍属于 M1-04/M1-05。

实现依据：[SQLite 表结构迁移](https://www.sqlite.org/lang_altertable.html)、[SQLAlchemy Session 事务](https://docs.sqlalchemy.org/en/20/orm/session_basics.html)、[Python JSON 解码行为](https://docs.python.org/3/library/json.html)。
