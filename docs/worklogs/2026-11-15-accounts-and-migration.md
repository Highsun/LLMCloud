# 登录、用户持久化与显式迁移

2026-11-15，起点 `feature/m4-observability-ui@3e2e5c3`。用户最新明确授权把队友登录、注册、用户数据持久化和迁移一并完成；本侧与 M5 稳定性/部署协调后修改共享入口。此前 A/B 历史保护范围按本次授权扩大，但未覆盖/重写远端其他工作，不提交真实数据或账户凭据，不代写共同验收结论。

新增可选账户模式及五个 auth 端点，默认关闭兼容历史单用户证据，新部署明确启用。复用现有错误、JSON/请求体边界和 SQLite 模型，新增 nullable 密码摘要和 opaque 会话表。密码使用随机盐 scrypt，会话仅存 token 哈希；HttpOnly/Strict cookie、到期注销、登录旋转、Origin检查、明确 CORS 和基础节流均已实现。前端加入登录注册入口、退出/到期处理与按账户分区的提交恢复状态。

归属沿用既有 `datasets.user_id`，任务由其数据集关联决定；数据集/任务 SQL 分页前过滤，任务创建、详情/指标/日志/Adapter/推理统一防止跨用户访问。原训练公开字段、Worker 五方法和 GPU 调度契约未变。`inference.py` 的授权调用由同轮 M5 主线协调接入，下载和所有 fetch/XHR 已支持 cookie credentials。

新增显式 auth 迁移和历史数据指定归属入口，应用前 SQLite backup、停服务声明、原公共 Worker 锁与事务重核；不自动迁移原库、不推断历史 owner。旧账户保留 NULL 口令，需要时用独立交互口令工具双 getpass 激活/重置，先备份并撤销该用户全部会话。陌生 schema 和外键错误拒绝。

验证包含真实 SQLite/HTTP 的 auth 组，既有任务 HTTP/迁移受影响组，以及原生 Windows Edge 的真实注册→上传→刷新→退出→另一用户隔离→窄屏错误密码→重新登录流程。浏览器为生产 API 和独立空库，无 GPU/Redis；不把它写成云业务验证或正式用户库升级。准确次数及原件摘要在 [结果文件](../testing/auth-results-2026-11-15.json)，项目全量回归和 M5 GPU 证据由同轮主线记录。

曾遇到两类环境问题均已修正：本机 checkout CRLF 导致原样例文件哈希与 LF Git 原字节不一致，已保持原样例逻辑内容、以 HEAD 原字节 LF 重生成契约；DrvFS 临时目录不能证明 Unix0600，将权限敏感回归切换到 E 盘承载的 WSL 原生 ext4。未据此放宽文件安全校验。导出由现有五个生成器完成，相关变更只有新增账户错误码，不手改生成 Schema。

接续见 [账户与迁移说明](../authentication.md)。原正式 DB、历史实验数据、模型、Adapter 与已有用户状态保持原样。当前仍需在实际采用账户模式的运行库停服务后执行显式迁移/指定归属或口令激活；云端启动、真实训练与用户归属业务回归由部署记录另证，不因新增账户功能自动宣告云端验收完成。
