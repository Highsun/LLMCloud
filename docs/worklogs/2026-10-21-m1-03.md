## 三、上传与错误行为

整个上传请求体最多 52,494,336 字节。合法 Content-Length 超限时在读取前拒绝；无此 header 或声明过小时，仍按 ASGI receive 的实际字节累计并在超限时返回 413。单文件最多 52,428,800 字节，解析器在暂存前计数，服务层共享扫描器继续限制实际文件与单行。

解析器最多接收 4 个文件 part、4 个文本 part，文本缓冲最多 64 KiB。解析完成后必须恰好一个 file、最多一个 name，重复/未知字段、文本 file 或文件 name 返回 422。name 的原始 UTF-8 编码不超过 1 KiB，仍由服务 Schema 执行空白、字符数与控制字符检查。

缺 boundary、错误格式、缺结束 boundary 或解析器硬上限返回 400；非 multipart 或非 identity Content-Encoding 返回 415。解析失败、接收超限、断连和取消均关闭已创建的缓存文件；缓存写盘失败也按 STORAGE_UNAVAILABLE/503 返回。

文件游标归零后，在线程池调用 service.create。持久化放在受管理的子任务中，服务器取消请求时也等待保存线程结束，再关闭上传流，避免一边关闭文件一边提交事务。保存开始后的取消或断网仍可能形成已提交资源，客户端不应自动重试 POST；先刷新列表，由用户决定是否再次上传。进程强杀和提交不确定的既有审计规则保持不变。

公共错误包含真实状态码、稳定 code、最多 10 条安全明细及 request_id；路径 UUID 错误为 422，合法但缺失为 404/DATASET_NOT_FOUND。路由 404、方法 405、未知异常 500 均为统一结构，405 保留 Allow；其他 HTTP 异常保留状态及必要 headers。

request_id 由服务端每次生成，覆盖客户端同名 header；应用响应包含 X-Request-ID，错误体与其一致。CORS 向配置的开发来源暴露 X-Request-ID 与 Location，早期 413/415 和 500 同样保留 CORS。标准 CORS 预检由框架处理，浏览器拒绝跨域、断网、上游非 JSON 错误仍需前端兜底。服务与异常诊断日志关联 request_id；离线服务调用显示 `request_id=-`。

**61 项测试通过**：9 项契约、25 项 HTTP/ASGI、5 项共享扫描器、16 项服务、6 项迁移。重点验证：

- 上传后文件原始字节、SHA-256、大小和行数一致，新应用连接仍能查到资源；重复内容生成不同 UUID。
- 固定分页、空页/越界页、巨大 page、未知/重复/空/非整数/越界 query；错误详情最多 10 条。
- multipart 字段形状、name UTF-8/编码长度、文件名、错误内容的物理行号和安全错误体。
- 真实 50 MiB 文件可接受，增加 1 字节返回 413；整个请求体逐块限制，包括无 Content-Length 和伪造偏小声明。
- 超过内存阈值的缓存文件，在畸形请求、超限、断连和取消时关闭；保存期间服务器取消不会提前关闭数据流。
- 缓存/落盘失败及数据库故障返回 503，未知错误返回安全 500；request_id 贯通日志和响应，CORS、Location、Allow 保持正确。
- 运行时 OpenAPI 与导出操作/引用 Schema 相同，所有引用有效，health/models 原有成功结构保持一致。

TCP 冒烟返回：`chunked_upload=201, list=200, detail=200, invalid_query=422, early_body_limit=413`。它启动隔离的 Uvicorn 服务，通过实际 HTTP 分块上传，并验证大 Content-Length 不发送正文也能收到 413。自动化上传均使用临时数据库和目录，没有向本机业务库登记演示数据。本机只读检查返回 schema current、数据集 0 条，临时/孤立/缺失/非法路径/不可读/哈希异常候选均为空。

新增 httpx 为默认 dev 测试组，uv.lock 中已有依赖版本保持；requirements 已按脚本导出，内容无需变化。锁定的 Starlette 对 TestClient 使用 httpx 提示弃用，当前测试可用；本次未顺带升级测试客户端或训练库。故障测试中的诊断日志为主动注入的异常。
