## 依据实际代码作出的决定

- MetricWriter 按 kind 保留单调步数，同 step 可以有 train/eval，write/flush 后才回调 SQL。现前端 after_step/Map(step) 会覆盖记录，因此拟改 source_id + 字节 cursor、offset 身份；HTTP 不修改 M2 原事件/指标文件。文件指标短时领先 SQL 是正常采样顺序，不据此伪造状态或删点。
- 任务日志为 JSONL 阶段/指标/安全失败记录，不是共享 Worker stdout；拟有限尾部、安全字段投影和明确截断/过滤状态，Worker 预检查失败没有 Trainer 日志也需合理显示。
- 正式产物审计严格限制输出根条目，下载 ZIP 必须在独立临时目录；完成快照/原共享 CPU 审计/实际复制哈希共同保护交付，不新增 SQL 列、不改 Worker 五方法 Protocol。单 API 进程的下载槽位与数据量上限先控资源，不引入缓存或对象存储。
- 当前下载在 await 后使用 selected.id，request 的 blob 分支直接 return Promise 后 finally 会先清理超时/abort 监听；05 必须固定任务身份并覆盖完整响应体，新增延迟 blob/任务切换行为检查。
- 现任务 OpenAPI 导出只选择两个 M3 路径，实施后须扩展真实已注册子路径；不能把规划写入假运行时接口。共享错误枚举变更时生成相关原契约，不保留两套手工 OpenAPI。
- 服务任务没有验证集入口，M4 不因此扩充 TaskCreate；无真实 eval 不画零线。同 step 两类用明确受控测试，真实训练验收核对实际存在的 train 记录。
