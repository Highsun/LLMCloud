## 实现

| 文件 | 行为 |
| --- | --- |
| frontend/src/api.js | request 支持可选 headers；ApiError 读取专用 error.task_id，同时保留状态、稳定 code、details、request_id 与不确定性；M1 FormData/上传协议不变 |
| frontend/src/task-submission.js、workspace.js | 单次意图冻结配置/UUIDv4 去重键；防双击；发送前保留意图，响应后保存 ID；sessionStorage 按 API 地址隔离，刷新不发 POST；存储不可用时提示 |
| TrainingPanel.vue | 只读取 TaskDetail.id；已知 ID 显示查询原任务入口；未知结果冻结原配置，用户明确确认时才用相同键/正文请求去重；明确准备新任务后才生成新键；刷新恢复已提交参数，跨数据集分页保留已选 ID |
| task-detail.js、TasksPanel.vue | 验证正式 id/status/config/步数/进度；移除 training_config 别名；显示 null 进度、真实步数、错误码/原因及时间；100% RUNNING 提示等待产物校验/状态提交，不自行判成功；默认显示配置快照 |
| TasksPanel.vue、ErrorNotice.vue、style.css | 已存任务提示查询状态；详情手动刷新/加载/错误；最近任务可直接查询；旧响应不覆盖新选择/关闭/隐藏页面；终态停止详情轮询，列表继续更新；M4/M5 操作依运行时能力禁用 |
| tests/task-submission.test.mjs、e2e/tasks.spec.mjs | 提交恢复/去重/失败、正式字段与进度、浏览器真实 HTTP/SQL、确认丢失、请求竞态和移动端回归 |
| testing/serve_task_api.py、playwright.config.mjs | 独立临时 API/SQLite/文件；复用原 create_app 和 M1 故障控制；仅此测试进程装配受控 Publisher 与仓储事件，不在产品添加控制路由；可选本机 Python/Chrome |
| frontend/README.md | 当前 M3 接入行为、恢复限制、真实/合成证据与执行说明 |

有任务 ID 的 DISPATCH_FAILED/DISPATCH_UNCERTAIN 只查询该 ID，不再次提交。没有 ID 的网络中断/超时等不确定结果，不自动重发；“确认原提交”使用原键与冻结正文：原记录存在则实际 API 返回 200，不重派；未保存时才创建。409 保留原意图，422 等明确客户端拒绝允许修正后重新提交。放弃未知意图会明确提示新任务可能重复。

sessionStorage 仅保留当前标签页最近一次提交的键、配置和任务 ID，不保存训练正文、上传文件或生成记录，不保证跨设备/关闭标签页后恢复。页面刷新后有 ID 时读取原任务；没有 ID 时仍需用户明确确认原提交。
