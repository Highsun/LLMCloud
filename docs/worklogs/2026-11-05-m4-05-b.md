## 实现

- createTaskDownload 在点击时捕获 id/规范文件名/序号和专属 AbortController，只允许当前选中且 SQL 详情为 COMPLETED 的任务。进度 100% RUNNING、排队/失败、非选中任务均不发下载请求；重入共用一次请求。保存使用已捕获 UUID，不在 await 后读取 selected.id，也不采用不受控 Content-Disposition 文件名。
- 切任务、关闭详情或离开任务页取消旧下载，并隔离旧成功、错误与 finally；忽略 abort 的传输替身晚到也不保存旧文件，不清掉新任务 busy/error。请求阶段有明确“取消下载”，取消后恢复按钮并允许用户主动重试；没有自动重试。
- fetchTaskAdapter 使用原 baseUrl，只发 GET /tasks/{UUID}/adapter、不接受客户端路径/查询。60 秒 timeout/调用者取消覆盖等待响应头、完整 blob 和基本签名检查，取消时 Promise 竞争及时结束等待，真实 fetch 仍收到 abort。计时器/外部及内部监听在相应 finally 清理，不在收到响应头时提前释放。
- 成功必须 200/application/zip（可有 MIME 参数）；HTML/JSON/空 MIME/206 不作为文件，取消未读的非法成功体。完整 body 后检查 PK ZIP 起始签名，避免伪装 MIME 的错误正文另存 ZIP。此检查仅为前端基本门禁，不重新实现 ZIP/清单/CRC/哈希审计；传输损坏/读取异常不保存。
- HTTP 错误经复用的原 responseError 显示 code/status/message/details/request_id，保留 Retry-After 整数并对 DOWNLOAD_BUSY 提示手动重试。取消、超时、网络中断和浏览器保存异常分别反馈，不改变 TaskDetail 或训练状态。
- api.js 仅增加原错误解析器的具名导出，并把原 raw=blob 成功分支改为 return await response.blob()，保留原 M1/M3 调用签名、JSON/统一错误和变更不确定性语义。新下载使用专用 helper；旧 blob 调用也不再提前清理超时监听。
