## 原规划补全与兼容影响

原四方法仓储无法实现“有效训练结果已产生但完成写入确认丢失后重新读状态”，因此增加只读 get_status(task_id) → TaskStatus | None。现为 get_status/claim/record_progress/complete/fail；DB 异常必须抛安全 TaskStoreError，不冒充不存在或失去归属。完成确认丢失时读取实际终态，不能在统一 except 中继续 fail 或删除有效产物。

执行结果固定 completed/failed/skipped/ownership_lost/reconciliation_required；eval/重复进度仍持有归属时返回 True 而不推进，False 只表示无归属/非 RUNNING/不存在。Protocol 为同步结构接口，不声称已有 SQL 并发保证。B 对这些新增细节的核对待完成；发生分歧在共享提交同步，不各写一份类型。

迁移清单新增 dataset_key 快照以及明确命名的 idempotency_key/request_sha256，与 Spec 字段一致；本次没有添加任何 ORM 列或执行任务迁移。M2 FailureCode、TrainingConfig 和训练契约保持不变。共享 HTTP 错误枚举是追加值，已重导出受影响契约；当前数据集路由没有新增任务错误行为。
