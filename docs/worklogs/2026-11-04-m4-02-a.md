## 代码及接口影响

- 新 services/task_files.py：Linux/WSL 从绝对配置根祖先起逐级目录 fd/O_NOFOLLOW，固定 UUID 子路径；O_NONBLOCK 打开后检查普通单硬链接文件，避免 FIFO 阻塞、链接/设备/目录越界。通过 pread 读取快照；结束时再验证命名路径对应原 inode、文件未缩短/新增硬链接。所有分支关闭描述符，不创建/改写训练文件。
- 新 services/task_observability.py：短事务读取现有 get_detail 后释放 SQL，再读文件。指标绑定任务 UUID/device/inode 摘要为 source_id，包装原 TrainingProgress，offset 为真实起始字节；保留 train/eval、零 Loss、UTC、半行不推进游标、终态空页/补拉和 SQL 步数暂落后 flush 的情况。
- 每次指标总读取不超过 512 KiB，含尾字节和最多 16 KiB+1 的直接前驱；完整行最多 16 KiB，序列化最多 1 MiB。检查行边界、前驱/当前页顺序与 total_steps；达到预算时保留完整后继行证明 has_more，不从文件头扫描。坏完整 JSON/重复键/非法 UTF-8/非有限值/超长行不跳过；COMPLETED 空指标或半行报 METRICS_CORRUPTED。
- 缺文件仅在无来源、零游标、SQL 零步数、非 COMPLETED 时自然返回 not_created；携旧游标而源消失为 409，已有步数/完成任务缺文件明确不可用。文件替换/缩短/非行边界拒绝继续，观测失败不更新任务状态。
- 新 services/task_log_projection.py：只从 LOG_DIR/tasks/{UUID}.log 尾部最多读 64 KiB；窗口完整候选取最后 tail 条再投影，不补旧行。按阶段和值验证，过滤未知/路径/自由文本 message/异常附加字段，指标复用原 TrainingProgress；failure 只保留任务匹配 UUID、受控 code/stage。diagnostic 最多 16 异常、每项最后 32 个安全 basename/function/正行号 frame。输出安全单行 JSON 文本，UTC 格式化本身不计过滤。
- 截断窗口的第一个可疑片段丢弃并置 truncated，不冒充完整记录；完整候选坏行逐行计 filtered_lines，半行置 tail_incomplete。已看到的日志通过线程安全、最多 4096 项的进程 LRU 记忆，零步文件后来消失也报错；跨重启/淘汰后不承诺保留此记忆，SQL 步数仍为持久判断依据。
- 新 api/task_observability.py，main 装配两条 GET：metrics 使用 cursor/source_id/limit，logs 使用 tail。复用原 multi_items 原始重复/未知查询拒绝、Pydantic 严格整数、UUIDv4、统一错误/request_id/CORS，成功 no-store，SQL/文件操作在线程池执行。不取 GPU 锁，不加载训练库。
- scripts/export_task_openapi.py 改为导出实际全部任务子路径，从真实 app.openapi() 生成；本次只有 metrics/logs 新路径，没有提前注册 adapter。更新旧阶段的“尚无指标路由”保护预期，保留下载/推理未发布检查。
- 新 scripts/check_task_observability.py，真实 TCP API/SQLite/MetricWriter 追加及投影冒烟；Publisher 和执行完成安排明确为隔离 CPU 替身，临时数据自动清理。CI 纳入该命令。
