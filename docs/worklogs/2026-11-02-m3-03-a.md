## 实现

- api/tasks.py：POST /api/v1/tasks、GET /tasks、GET /tasks/{task_id}，全部返回真实 SQL DTO；创建 202、同键重放 200，Location 与 X-Request-ID 可查询/追踪。过滤后分页、超出末页空结果、详情 config/null 进度沿用共享契约。
- 严格原始请求解析：未压缩 UTF-8 application/json、重复 JSON 键（含嵌套）、NaN/Infinity、顶层类型、未知字段/查询、重复查询/去重请求头、UUIDv4；只返回安全校验详情，不复制正文/异常输入。
- ASGI 层按路由区分 M1 multipart 和任务 JSON 限制；POST 任务 64 KiB 声明超限不读正文，真实分块也计数，假 Content-Length 不绕过。M1 50 MiB + 64 KiB 上传限制和错误保持原行为。
- services/tasks.py：先独立 DB 提交，再一次 Publisher；重放不发布。accepted 后只条件标 QUEUED 并重读真实状态；not_sent 只有实际条件结束 PENDING 为 FAILED 才返回 DISPATCH_FAILED；unknown/状态确认失败保留原 task_id、返回 DISPATCH_UNCERTAIN，不覆盖 RUNNING/终态、不自动重发。
- 专用 TaskServiceError 复用现有统一错误核心；持久化后派发 503 使用 TaskSubmissionErrorResponse 的 error.task_id/Location，未知创建 ID 时使用普通 DATABASE_UNAVAILABLE。CORS 增加 Idempotency-Key，继续暴露 X-Request-ID/Location，不启用凭据。
- services/task_dispatch.py：不导入 Worker/Trainer，按 worker.train 名称发送仅含 task_id 的 args，使用保存的独立 celery_task_id 和训练队列。客户端延迟到发布时创建；API 冷导入不加载 Celery/Kombu/Redis/Worker/训练库，也不联网。
- 核对锁定 Celery 5.6.3/Kombu 5.6.2/redis 6.4.0 源码并查阅官方文档：Kombu connect() 默认重试一次，所以实现显式 ensure_connection(max_retries=0)；发送 retry=False、关闭 Celery 发布重试，并将 Redis 命令重试设为 0。连接前失败与发送阶段异常区分，清理失败不抹去已确认结果。
- Settings/.env.example 新增 TASK_PUBLISH_TIMEOUT_SECONDS，默认每操作 1 秒，范围 >0 且 ≤5；建连和读写有超时，不声称整个请求严格 1 秒结束。仅单 Redis URL，不引入备用 Broker/自动恢复。
- api/task_openapi.py + scripts/export_task_openapi.py：从真实注册 app.openapi() 导出 tasks.openapi.json（server /api/v1、相对 paths）。503 anyOf 准确包含普通错误/带 ID 的专用错误，查询枚举引用可解析。手动解析请求的 Schema 是来自共享类型的运行时元数据，不是另一份手写 OpenAPI。
- 接 HTTP 边界时修正 M3-02 超大越界 page 的 SQLite OFFSET 溢出：已知 offset 超过 total 时直接返回空页，保持契约的 200，而不是错误 503。
- CI 增加任务运行时 OpenAPI --check；共享入口、API/规划/记忆/架构/需求和日志索引已同步，旧接口/类型版本不变。
