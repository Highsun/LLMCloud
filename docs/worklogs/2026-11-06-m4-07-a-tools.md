- `scripts/check_m4_acceptance.py`：`--check` CPU 浏览器预检；`--gpu` 显式真实执行；`--gpu --manual` 为双方人工操作保留本轮服务。GPU 入口要求干净 Git、固定 revision、完整离线缓存，证据仅创建在忽略目录 `data/acceptance/m4-07/{新UUID}`，拒绝复用/越界/链接根目录。
- 复用 M3 的生产 API/Worker 生命周期辅助方法，覆盖 M4 配置、Vite 严格端口和清理；不执行 M3 两步用例或故障 Worker。建立独立 DATA_DIR/SQLite、私有 Redis Unix socket/DB/队列；共用真实 LOG_DIR/worker.lock。API 和 Worker 环境保持相同内部步数，默认 40，单 Worker/并发 1。
- `scripts/check_m4_browser.mjs`：实际页面上传、连续提交两个任务、观测第一条任务、终态原始 HTTP/曲线/日志对照、刷新恢复、390px 检查、实际下载两个 ZIP。两条消息真实入队且浏览器就绪后才启动 Worker；训练中不暂停、不补指标。JSON 交接文件采用写临时文件再 rename，避免 Python 读取半份文件。
- A 自动门槛还包括两条 SQL 区间不重叠、GPU 分配/干净提交/SQL 完成投影与清单一致、至少 5 个真实 train 点、跨两个活轮询且完成前页面至少展示 5 点。旧任务 ZIP 下载起止须落在另一条任务真实优化器事件之间，不能只凭加载期 RUNNING 宣称下载与训练并发；太快则失败并增加真实步数重跑。
- `scripts/m4_acceptance_support.py`：新的证据目录门禁、串行时间核对、调用原产物审计。下载独立限量解压，只允许源清单的精确文件集合，拒绝重复/额外/越界/链接/加密条目，读取过程中核对大小、CRC、实际哈希，再执行原 CPU 审计并比较原清单。失败清理本次解压目录，不覆盖既有目录。
- 关闭本轮 browser/Worker/API/Vite/Redis；单项关闭失败仍尝试其他清理，记录 cleanup_errors 并拒绝自动通过。保留任务文件、原日志、报告、HTTP 观测、截图/trace、下载包及审计结果。下载工作区为空及第二次下载成功也属于自动检查。
- `automated_passed` 只描述 A 自动部分；人工字段始终 pending。人工入口不使用自动机器人，新上传/提交由 B 实际操作，会话关闭状态仅为 `manual_session_closed_pending_review`；到时仍在训练应保留记录并按停机对账流程处理，不自动修状态或重投。

## 实际验证

独立 CPU Python 环境 `/tmp/llmcloud-ci-env` 沿用锁定基础依赖，未裁剪训练 `.venv`。本机 Chromium、共享库和中文字体通过已有环境变量提供，工具未硬编码这些机器路径。

```bash
# 在项目根目录，以下命令用本机已有 CPU 环境执行。
/tmp/llmcloud-ci-env/bin/python scripts/check_m4_acceptance.py --check
/tmp/llmcloud-ci-env/bin/python -m unittest discover -s tests -v
LLMCLOUD_M4_TOOL_BROWSER_TEST=1 /tmp/llmcloud-ci-env/bin/python -m unittest discover -s tests -p test_m4_acceptance.py -v
node --check scripts/check_m4_browser.mjs
```

运行浏览器时另设置本机 `PLAYWRIGHT_BROWSERS_PATH`、`LD_LIBRARY_PATH`、`FONTCONFIG_FILE`；移机使用已安装的 Playwright 环境即可，不照抄本机临时路径。

结果：

- `--check` 实际 Chromium 启停通过，报告 `gpu_started=false`、`services_started=false`；CPU 环境未安装训练包，按实报告 available=false，不把预检当 CUDA 检查。
- 全部后端回归 **406 项，1 项 opt-in 浏览器检查默认跳过，其余通过**；完整进程/HTTP 检查在允许本机子进程与 loopback 的环境执行。
- 新任务检查 **12 项全部通过**（显式启用浏览器项），覆盖目录防覆盖/逃逸、串行/时区、ZIP 原字节/审计、缺失/重复/额外/篡改/CRC、既有解压目录保留、CPU 合成产物不能冒充 GPU、显式开关/干净提交、CPU 无训练库导入、隔离配置/内部步数传递、关闭失败后的资源回收。
- 其中机器人整流程连接真实生产 API/SQLite/文件读取/ZIP/Vite/Chromium，Publisher 和执行输入明确为测试内 CPU 替身，无 Redis/Worker/GPU；两条合成任务各 5 点、桌面/390px、最终日志/曲线、实际 ZIP 和独立原审计通过。它检查的是新机器人本身，**不是 M4-07 GPU 通过记录**，GPU 编排不会接受这种零 GPU 分配产物。
- 该整流程测试首次暴露了机器人刷新后默认打开配置页的问题，修正为核对曲线前显式选择曲线 tab；未改页面或放宽产品断言。CPU 替身第二条任务等待真实下载交接后才完成，只用于确定性测试，生产 GPU Worker 不读取该交接文件或等待它。
- 五项导出器 `export_dataset_contract.py`、`export_training_contract.py`、`export_task_contract.py`、`export_task_openapi.py`、`export_observability_contract.py` 的 `--check` 全部通过；JS 语法检查通过。
