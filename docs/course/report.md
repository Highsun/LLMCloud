# LLMCloud 云端大模型微调平台课程报告

## 摘要

LLMCloud 将 Qwen2.5-0.5B-Instruct 的 LoRA 微调封装为异步 Web 服务。用户通过浏览器上传 JSONL 数据、配置训练任务、查看真实 Loss 与日志、下载 Adapter，并比较基础模型与微调模型的回答。FastAPI 负责接口和元数据，Redis 与 Celery 将 GPU 任务交给单 Worker，SQLite 与受控文件目录记录业务状态和训练产物。

项目已完成真实训练、产物审计、独立进程重载及本地端到端验证。正式 E01 使用 120 条经审核样本，按问答族划分为 96 条训练、16 条验证和 8 条测试。1 epoch、12 个优化器步的训练耗时 37.405 秒，96 个 LoRA 张量均发生变化，基础权重哈希不变。一次性留出评估的 token 平均 Loss 从 4.395695 降至 4.024455，困惑度从 81.100942 降至 55.949788。12 道固定题上，用户人工评分与另一侧 AI 代评的偏好方向相反，当前证据不足以确认稳定的回答质量提升。

云端运行结论需要在目标服务器完成业务回归后单独记录。本报告将已实现能力、已实测范围与部署目标分别说明。

本次材料整理收尾于 2026-11-16，原测试、实验与录像日期仍按实际 2026-11-15 记录。材料支持已验证的 B 分支工作区，测试基线为 3e2e5c3 加本轮修改。后续 fetch 发现队友 feature/user-system 的 a935316 与本侧用户表结构不兼容，双方分支独立保留、尚未合入；本材料不能作为 A+B 合并版本的验证证明。

## 1 项目目标与范围

课程目标是在单 GPU 资源下实现可追溯的微调服务，重点验证 HTTP 服务、异步队列、GPU 串行执行、数据与产物管理以及部署复现。核心业务流程为数据上传、任务创建、训练执行、过程观测、产物交付和测试推理。

基础版本固定使用 0.5B 模型和普通 LoRA。数据格式为 UTF-8 JSONL，每行包含 instruction、input、output。项目采用单机 SQLite 和本地受控文件目录，避免在基础交付中加入多 GPU、Kubernetes、分布式存储、计费或断点续训等额外复杂度。用户系统的本轮实现和迁移验证在对应代码及记录中独立说明，不据此扩大已测云部署范围。

## 2 系统设计

### 2.1 服务职责

Vue 3 与 Vite 前端调用 FastAPI 接口。API 校验数据与参数、持久化任务元数据，再向 Redis 发布只包含任务 ID 的 Celery 消息，不在 HTTP 进程加载 GPU 模型。唯一 GPU Worker 领取任务后读取固定快照，调用独立 Trainer，保存并审计产物后更新终态。训练和推理共用 GPU 资源保护，避免同时加载两份模型。

SQLite 是业务状态来源，文件目录保存不可变数据集、模型缓存、指标、日志与 Adapter。训练器只依赖内部输入、事件和输出契约，不依赖 HTTP、Celery 或 SQL。Trainer 唯一写入 metrics.jsonl 并 flush 后回调同源事件，Worker 不重复写指标，前端不生成虚构 Loss。

### 2.2 异步状态与幂等

任务状态包含 PENDING、QUEUED、RUNNING、COMPLETED 和 FAILED。API 在派发前提交元数据。仓储通过条件更新和领取令牌保护状态，避免重复消息启动重复训练，也避免排队更新覆盖已开始的 RUNNING。派发明确未发送与发送确认未知分别处理，确认未知时保留原 task_id，不自动重投。

Worker 完成真实文件保存与独立审计后才返回成功。异常退出后的恢复工具先只读检查，显式应用前要求服务停止并取得公共进程锁。恢复保留诊断原因，不承诺自动重训或断点续训。M3 历史真实 GPU 验收与后续本机网页证据分别保留原运行身份。

### 2.3 可观测与产物交付

指标接口使用来源身份和字节游标增量读取，保留同一步的 train 与 eval 记录。前端按来源与 offset 合并，任务终态补拉尾页和最终日志。日志接口有行数和字节上限，并投影安全字段。

下载仅允许 SQL 已完成且固定快照、manifest 与原 CPU 审计一致的任务。服务在独立临时区复制、重新核对哈希并打包，不污染原输出。前端在完整响应体读取期间保持取消和超时，切换任务后隔离旧响应。训练和下载可并行，因为下载不占 GPU。

### 2.4 账号与数据归属

账户层提供注册、登录、当前用户查询和注销。密码以独立随机盐的 scrypt 摘要保存，随机会话 token 通过 HttpOnly、SameSite=Strict Cookie 传递，数据库只保存 token 摘要和过期时间。登录旋转会话，注销和到期后失效，前端不把口令或 token 放入浏览器存储。新部署显式开启账户模式，历史关闭账户的受限演示不能当作生产访问控制。

上传登记当前用户，数据集列表在计数和分页前按 owner 过滤，任务通过不可变的数据集关联继承归属。任务创建、详情、指标、日志、下载和推理均检查相同归属，他人 UUID 与不存在资源返回一致的 404。退出与切换账户清理页面缓存，所有用户仍共享唯一 GPU Worker。

旧 SQLite 使用只读检查、停服、取得公共锁、备份和显式应用的迁移流程。原用户 UUID、原数据和归属保持可追溯，不把无 owner 的历史数据自动分给第一个注册者，不凭空给旧账户生成凭据。迁移与归属分配均有独立参数和检查。本轮账号验证使用隔离数据库，通过 12 项 CPU 检查及真实 Edge 浏览器注册、登录、刷新持久化、注销、跨用户隔离与 390px 模拟布局检查，没有迁移或重分配既有正式数据库。

## 3 实验设计

### 3.1 数据与防泄漏

E01 正式语料共 120 条、26 个问答族，协议 v2.0.0，审核状态 reviewed，随机种子 42。按族划分训练、验证与测试，降低同族近似问答跨集合造成的泄漏。训练集 96 条、22 族，验证集 16 条、2 族，测试集 8 条、2 族。准备工具复用上传使用的严格扫描器，并保存 provenance、review 状态及 SHA-256 清单。

正式 build_id 为 8cf9ede8899f618a，数据 manifest SHA-256 为 88e905f2aaa709db97af7f659a7fb1c8e2de4a786f180ef925d1937b7531c550。训练和标签检查不读取测试正文。12 道固定对照题与 8 条留出测试不是同一组题，冻结题不参与调参。

### 3.2 冻结参数与运行身份

模型与 tokenizer 均固定为 Qwen2.5-0.5B-Instruct，revision 为 7ae557604adf67be50417f59c2c2f167def9a775。实验在 RTX 3060 Laptop 6GB、E 盘承载的 WSL2 Ubuntu 环境离线执行。LoRA 参数为 r=8、alpha=16、dropout=0.05，目标层 q_proj 与 v_proj；学习率 0.0002、batch=1、梯度累积 8、最大长度 512、BF16、seed=42，完整 1 epoch，不覆盖 max_steps。

实际运行代码为 390a7d9 加当时未提交的四文件补丁，补丁后续冻结为 2d8ab50。原始清单保留实际 dirty 基线，不改写为 clean。正式 task_id 为 8099c629-36a0-418f-ba7b-80a6e6c0e75f。该实验通过独立 Trainer CLI 完成，不能作为新增 Web 或云端运行的证据。

### 3.3 评估方法

训练结束并退出进程后，12 道固定题分别在新进程重载，使用相同 prompt、chat template、revision、greedy 解码、num_beams=1 和最多 192 个新 token，得到 24 份实际回答。部分回答达到输出上限，按实际结果保留，没有为改善评分而修改预算重跑。

一次性留出评估在冻结参数后执行。每模型每样本只进行一次 teacher-forced 前向，使用原预处理的回答标签和模板 EOS，causal shift 后以 float32 交叉熵求和，再除以有效监督 token 数。该 token 加权 NLL 与 Trainer 的验证 Loss 聚合口径不同，不能直接横向比较。

### 4.3 评分来源与分歧

两份评分在揭晓身份前保存原字节快照与 SHA-256。B 侧为用户个人评分，A 侧收到的文件声明由 GPT-6 Astra 代评，不能描述为两位成员亲自完成的独立人工盲评。每模型每来源满分 48，包含 12 题的准确性、清晰度与边界维度。

| 评分来源 | 基础模型 /48 | Adapter /48 | Adapter 减基础 |
| --- | ---: | ---: | ---: |
| 用户个人评分 | 25 | 33 | +8 |
| A 侧文件声明的 AI 代评 | 27 | 21 | -6 |
| 描述性相加 满分 96 | 52 | 54 | +2 |

两来源偏好方向相反。混合总分只作描述，不表示人类与 AI 的判断可以互换，也不是统计显著性结论。维度合计中准确性由 23 降至 19，清晰度由 20 降至 19，边界由 9 升至 16，总分的微小增加主要来自边界维度。

B 表 C09 回答 B 的手写总分为 2，分项为 1、0、0，按冻结的分项求和规则计为 1，原件不改写。B 侧未提供理由，报告不补造解释。C05 相对改善但仍有事实问题，C12 评分不变，C01、C03、C08、C10 的描述性均分下降，均予保留。

### 4.4 实验结论与限制

E01 完成可追溯的真实 LoRA 训练、产物审计和独立重载。小型留出集 Loss 与困惑度下降，用户人工评分与 AI 代评的偏好方向相反，当前证据不足以确认稳定的回答质量提升。样本少、测试族少、固定题生成上限和评分来源不同均限制结论外推。后续若补充人工复核，应标注解盲后复核，不能追认本次为双人人工盲评。

## 5 稳定性验证

已有真实本地证据包括网页上传、两任务训练区间不重叠、200 步活指标与文件一致、训练活动期间下载旧产物、限速取消后重新下载并独立审计，以及推理对比、GPU_BUSY、ARTIFACT_NOT_READY 和空闲重试。本轮最终全量 CPU 回归运行 448 项，447 通过、1 项原可选浏览器跳过，耗时 58.663 秒，已包含 12 项账号与 5 项代码来源专项，不重复相加。五项正式契约检查全部通过；前端 135 项及生产构建通过。前述历史证据与本轮新执行结果分别保留实际基线。

2026-11-15 在真实模型、Redis 与 Worker 上完成 6 组推理故障验收。运行基线为 3e2e5c3 加当轮未提交修复，auth=false 隔离，使用既有工程测试 Adapter，不把该结果写成用户系统下的 GPU 联合验收或 E01 新实验。

| 故障场景 | 实际结果与恢复 |
| --- | --- |
| 90 秒服务端超时 | 确认首个 CUDA token 生成后受控暂停 95 秒，90.063 秒返回 504 / INFERENCE_TIMEOUT；清理期间返回 409 / GPU_BUSY，清理后 compare 返回 200 |
| Worker 异常退出 | 首个真实 token 后注入 SIGKILL，后继恢复将原请求置为 500 / INFERENCE_FAILED，随后重试返回 200 |
| 模型缓存缺失 | 使用独立缺缓存环境返回 503 / MODEL_NOT_CACHED，原缓存未改，恢复后推理返回 200 |
| 领取前派发确认丢失 | 返回 503 / INFERENCE_UNAVAILABLE，实际迟到消息不重复生成，后续重试成功 |
| 领取后确认丢失与重复消息 | 使用真实 Redis 重复投递，等待原请求结果，后续推理成功 |
| 故障后健康检查 | compare 返回 200，基础模型与 Adapter 均完成生成 |

19 项独立 CPU 推理回归通过，覆盖真实 SQLite 预留与领取竞争、训练优先、迟到和重复领取、取消后占用直到清理、超时不提前释放、遗留请求恢复、保留期清理、畸形请求和派发确认丢失。此套件的 GPU 与产物使用替身，不计作真实模型执行。

10 项真实 Edge 浏览器回归通过，接口使用明确的 fixture 拦截，覆盖两种模式、两类 409、取消和切任务、切模式、离开缓存页面及 390px 布局。客户端使用真实浏览器时钟等待，配置预算 120000 毫秒，实测 120488 毫秒出现超时，输入保留且未自动重发，手动重试成功。该 120 秒浏览器用例不加载 GPU，与生产 90 秒服务端预算和真实浏览器 GPU 端到端录像分别记录，不能混称 fixture 回答为模型生成。

## 6 部署设计与验证方法

### 6.1 单机部署结构

目标部署包含前端静态服务、CPU API、Redis 和唯一 GPU Worker。前端同源代理 API，服务监听受限地址。API 不安装或加载训练模型，GPU Worker 使用锁定依赖并挂载同一数据、数据库、模型缓存与产物根目录。Redis 不直接暴露公网，数据库使用单机持久化目录，GPU Worker 保持并发 1 和预取 1。

部署配置与操作命令以仓库部署说明为准。模型缓存准备和完整 revision 检查先于服务启动，运行期使用离线加载，避免演示时临时下载权重。配置、秘密与运行数据通过环境和持久化目录提供，不写入镜像或 Git。用户系统迁移必须先停止相关服务、备份并检查，再显式应用，不以删库重建代替迁移。

### 6.2 持久化验收

重启验证应先记录冻结提交、Compose 配置、数据库及文件摘要，完成真实上传、训练、观测、下载和推理。停止并重启容器时保留持久化卷，之后使用同一用户重新登录，核对数据集与任务仍可查询、原 Adapter 仍可下载且审计通过、固定模型缓存仍可离线加载，随后执行一次新的推理。数据库可打开、目录存在或镜像构建成功均不能替代业务验证。

应分别记录服务重启和主机重启的范围。只完成服务重启时不能声称主机重启通过；本机 Compose 成功也不能声称云端部署成功。云机可用后，在目标环境重新完成完整业务回归，记录云端地址的访问范围、GPU 型号、版本、数据持久化位置和实际运行证据。

### 6.4 容器实测缺陷与修复后闭环

完整 GPU 容器首次训练发现精简镜像缺少 .git，而训练环境记录依赖 Git 元数据，任务 7d107c92-264d-4b28-ba74-d96197cd243e 以 MODEL_LOAD_FAILED 结束。原失败任务与报告保留，没有将镜像构建成功或 CUDA 可见写成训练成功。修复采用镜像构建来源清单，记录提交、dirty 状态和实际源码 SHA，并在运行时验证完整文件集合和每项摘要，以便无 .git 的镜像仍能提供真实代码来源。5 项专项检查通过后重新构建镜像，再运行真实业务验证。

修复后，API、前端、Redis 和 GPU Worker 四服务全部运行于 E 盘 WSL ext4 上的容器中，使用私有 CDI 将 RTX 3060 交给唯一 Worker，账户模式开启。新账号通过真实浏览器完成上传、2 步训练、Loss/日志、下载、compare 和 390px 模拟布局，未 mock API 或 GPU。task_id 为 18c617b2-c024-4911-85f7-cd2f35dd97d1，训练耗时 19.016450 秒，最终 train Loss 为 3.8488，compare 中基础模型与 Adapter 各生成 64 token。
